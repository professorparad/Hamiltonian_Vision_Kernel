# Phase-transition section: scope and framing

## Reviewer ask

"Reduce or move the phase-transition section unless proper finite-size scaling and
preregistered detection criteria can be provided." Also: "phase-transition and
effective-temperature terminology is risky... should be called optimization diagnostics
unless supported by finite-size scaling and a clear thermodynamic correspondence."

## What already existed

`Main2/newHVK/run_finite_size_phase_transition.py` and `run_critical_temperature.py`
already implement the corrected, noise-free, eval-mode change-point diagnostic (median +
2*std threshold on step-to-step change), N in {4,6} only, 2 images, 2 seeds. The paper
already frames this carefully ("not a thermodynamic phase transition... An earlier
version was withdrawn after a provenance audit", `paper_hvk.tex` around
`sec:phase_transition`) — the corrected version is NOT the reviewer's main target; the
concern is about how much weight/space it's given and whether "critical temperature" /
"susceptibility" language reads as physical overinterpretation regardless.

## What this effort adds

`Main2/newHVK/run_qubit_energy_phase_transition.py` (new): extends the corrected
protocol to N in {2,4,6,8} (previously only 4,6), 5 images (Monalisa + the same 4 CIFAR
images used in the hardware pilot, previously just 1-2 images), 2 seeds, and tracks
energy + R_ES ("temperature") simultaneously with the order parameter at N=6 to check
whether their detected change epochs coincide.

`Main2/newHVK/plot_qubit_sweep_combined.py` (new): combines all four N values into ONE
figure per image (order parameter + susceptibility panels, mean±std over seeds, dashed
vertical lines at each N's detected critical epoch) — requested directly by the project
owner's supervisor to see the critical-epoch shift across qubit count at a glance,
instead of four separate per-N images.

**Important provenance note** (do not skip this when writing up results): the exact
two-panel "order parameter + energy" / "susceptibility" plot *style* the supervisor
initially referenced is generated by `python_library/src/hvk/training/phase_media.py`'s
`save_order_parameter_plot`, fed by the ORIGINAL per-image training pipeline
(`training.py`'s `data_generator`). The paper explicitly documents that pipeline's
per-image single-run traces as **withdrawn after a provenance audit** (training-mode
forward pass injects Gaussian observable noise that confounds the trace). The new
scripts in this effort reproduce the same visual style but compute it correctly, via the
paper's already-corrected noise-free eval-mode protocol — confirmed with the project
owner before building anything, given the risk of silently reintroducing discredited
evidence.
